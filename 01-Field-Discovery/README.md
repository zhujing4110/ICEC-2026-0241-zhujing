## 四、课题 04 怎么测（模板已备）

两份文件：

| 文件 | 内容 |
|---|---|
| `raw_data/task04-queue-throughput.csv` | 15 行时序（每 2 分钟 1 行），**主数据** |
| `raw_data/task04-queue-meta.csv` | 场景、地点、日期、开始时间、窗口数、**起始排队人数**，由脚本自动写 |

**用脚本记，别手抄**（它会卡时间、提醒、直接写表）：

```bash
# 食堂窗口
python tools/task04_queue_timer.py --kind 食堂 --place "二食堂 3 号窗口" --counters 2

# 教学楼电梯口
python tools/task04_queue_timer.py --kind 电梯 --place "A 座 1 层电梯口" --counters 3
```

中断了不用重来，加 `--append` 接着记（会沿用上一次的开始时间与起始排队人数）。

**每次要输入四个数**：

| 读数 | 口径 |
|---|---|
| 当前排队人数 | 站着等的人（正在打饭／已进轿厢的不算） |
| 过去 2 分钟到达 | 新排进队伍的人数 |
| 过去 2 分钟完成 | 拿到饭离开／上电梯走掉的人数 |
| 单次服务耗时 | 挑一个人从开始点单计时到结束（秒）。懒得掐就给空，脚本按「120 秒 ÷ 完成人数」折算并在备注里标出来 |

**开测瞬间的排队人数要单独填**（脚本第一个问题）——这是时序曲线的起点，缺了它平均等待时间会偏。

**四条会让数据变味的纪律**：

1. 站在能同时看到**队尾和窗口**的位置，别站进队伍里（你会改变被测对象）
2. 窗口中途增减、有人插队、机器故障，全部写进该行「备注」
3. 记的必须是**同一个窗口/同一组电梯**，中途换对象等于换了样本
4. **同框照在测量过程中拍**：队伍 + 窗口招牌 + 你的手或身影进同一个画面，别事后补拍

**测完一键核算**（打出可直接粘进报告的表格与指标）：

```bash
python tools/task04_analyze.py
```

它算到达率 λ、单窗口服务率 μ、服务强度 ρ=λ/(c·μ)、平均队长 Lq、平均等待 Wq=Lq/λ，并自动指出队列峰值出现在第几分钟、ρ 是否 ≥1（供给侧瓶颈还是瞬时聚集）。**归因结论仍要你自己写**——"窗口开了三个但只有一个在打菜"这种事脚本看不见。
