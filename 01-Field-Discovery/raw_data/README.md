# raw_data 说明：哪些是真数据，哪些是空表

评审打开这个目录时，第一眼需要分清两件事：哪张表有数值、哪张表只是模板。这里先讲清楚，避免逐张打开猜。

| 文件 | 性质 | 状态 |
|---|---|---|
| `task10-batch-audit.csv` | 课题 10 审计表 | **有数据**。脚本侧耗时为实测（重复 3 次取中位）；人工侧为估算模型（单件成本按动作拆解，口径见 `report.md` 第 1 节），表内不设实测列，倍数标注「按估算」 |
| `task10-benchmark-result.json` | 课题 10 两次运行的原始计时 | **实测**，由 `tools/task10_benchmark.py` 生成 |
| `task10-repo-inventory.csv` | 课题 10 任务 C 产物（文件清单） | **实测**，同上脚本生成 |
| `task02-phone-thermal.csv` | 课题 02 时序表 | **空表**（24 行结构，数值列全空）——本课题**本次未采集数据** |
| `task02-phase-start.csv` | 课题 02 四段起点读数 | **只有表头**——同上，未采集 |

三点补充：

1. **空表不等于占位**。课题 02 交付的是采样设计（`report.md` 第 2 节）、记录脚本（`tools/task02_timer.py`）、核算脚本（`tools/task02_analyze.py`）与表结构，数据本身本次没有采。报告对应章节已明确写「未采集」，没有填任何推测值。
2. **估算与实测分列存放**。凡是估算值，列名里都带「估算」；凡是实测值，列名里带「实测」。两列不混用，倍数由它们相除得到，可信度等于估算那一边——报告里对此有单独说明。
3. **人工侧没有另设实测列**。本次未做逐项掐表，估算就是唯一口径，表里不留空的「实测」列——空列容易被读成「忘填」，写明「估算」则是明确的方法选择。
