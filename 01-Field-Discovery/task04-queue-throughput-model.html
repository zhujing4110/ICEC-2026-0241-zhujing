00 摘要与核心结论

先给结论：排队系统的瓶颈不是"平均到达率"，而是峰值利用率 ρ 与 1 的距离。

结论 1 · 排队存在"膝部"，ρ ≈ 0.85 是分水岭 在食堂基准场景（λ = 40 人/分钟、12 个窗口、单窗 3.6 人/分钟）下 ρ = 0.926，平均排队 13.6 秒 / 9.1 人；把 ρ 压到 0.79（错峰、增开窗口或提速任一手段）后，排队降到 约 2 秒 / 1.3 人——利用率只降 14%，等待时间却下降 85% 以上。等待时间对 ρ 是超线性的（∝ 1/(1−ρ)），这是所有扩容决策的理论依据。
结论 2 · 电梯基准方案是不稳定系统（ρ > 1），加梯不是唯一解 基准（4 部 13 人梯、RTT 112 s、λ = 30 人/分钟）运力仅 27.9 人/分钟，ρ = 1.077；每 5 分钟净积压 10.7 人，30 分钟早高峰结束时候梯队列会累积到约 64 人，且不会自行消散。单独"加 1 部梯"（ρ→0.862）或单独"目的层群控使停站从 5 降到 3"（ρ→0.942）都能转稳，后者不增加硬件成本，但余量更小。
结论 3 · 削峰的性价比通常高于扩容 把 λ 从 40 降到 34（错峰下课 15% 或预约取餐），食堂排队即降到 2.2 秒，效果等同于增开 2 个窗口或把单窗服务从 16.7 s 缩到 14.3 s。削峰改变的是需求曲线，不增加固定成本；扩容改变供给，边际收益随 c 增大而递减。工程上优先削峰 + 小幅提速，再考虑硬件。

01 问题界定、假设与符号表

两类场景共用"到达过程 → 排队 → 服务台 → 离开"的结构，差别在服务机制：食堂是一人一服务，电梯是一批一服务。

1.1 问题描述

  • 食堂：午餐高峰 11:50–12:20（30 min）集中到达，学生选窗口排成一队或多队，打菜+收银为一次服务。求：吞吐上限、平均队长、平均等待、需要多少窗口。
  • 电梯：早高峰上行，乘客在首层候梯，电梯按"上行—停靠—回落"循环运行，一次最多载 K 人。求：单梯往返时间、群梯运力、5 分钟输送能力、平均候梯时间、是否会无限积压。

1.2 模型假设

假设食堂（M/M/c）电梯（M/D/m 近似）合理性 / 影响
到达过程泊松流，率 λ（人/min）泊松流，率 λ（人/min）下课/上课是"批量触发"，短时内近似泊松；实际更聚集 → 模型偏乐观
服务时间指数分布，单台率 μ（人/min）近似确定型 RTT（变异系数小）人工服务波动大，指数假设合适；电梯行程确定 → 用 M/M/m 会高估等待约 2 倍，故引入 Allen–Cunneen 修正
排队规则FCFS，单队列多服务台 cFCFS，m 部电梯，每批 ≤ K 人若食堂为"每窗口各排一队"，性能略差于单队列
系统容量无限等待位无限等待位现实中有人会放弃排队（balking），会低估放弃率

一个必须说清的概念：吞吐率 ≠ 运力 稳态吞吐率 = 单位时间实际被服务完的人数，稳定系统里它恒等于 λ（来多少、走多少，受需求限制）；运力 C = c·μ（或 m·K·60/RTT），是系统上限（受供给限制）。当 λ < C 时吞吐 = λ；当 λ ≥ C 时吞吐被钳位在 C，差额 λ − C 全部转化为队列净积压。本报告所有"吞吐率"结论都按这个定义给出，避免把"运力"误报成"实际吞吐"。

02 模型一：食堂窗口 M/M/c（Erlang-C）

求解稳态生灭过程，得到等待概率、队长、逗留时间的闭式解；再用参数扫描定位"膝部"。

2.1 稳态解

记 a = λ/μ，ρ = a/c。当 ρ < 1 时，稳态概率 pn 由生灭方程给出，归一化后：

P0 = [ Σn=0c−1 an/n! + (ac/c!)·1/(1−ρ) ]−1 // 归一化常数
Pwait = (ac/c!)·1/(1−ρ) · P0 // Erlang-C：到达需排队
Lq = Pwait · ρ/(1−ρ) // 平均排队人数（关键：含 1/(1−ρ) 爆炸项）
Wq = Lq/λ ,   W = Wq + 1/μ ,   L = λ·W = Lq + a // Little 定律
吞吐 = min(λ, c·μ) ,   净积压速率 = max(0, λ − c·μ) // 人/min

数值实现用对数域 n·ln a − lnΓ(n+1) + log-sum-exp 计算，避免 c 较大时 ac/c! 溢出；ρ ≥ 1 直接判不稳定。

03 模型二：电梯群批量服务（RTT 运力模型）

电梯不是"一人一服务"，而是"一次行程服务一批 K 人"，必须先把 RTT 算出来，再折算成人/分钟的群梯运力。

3.1 往返时间 RTT 与运力

RTT = 2(H−1)·tf + (S+1)·ts + 2·K·tp // 运行 + 停站开关门/加减速 + 上下客
单梯运力 = K · 60/RTT  (人/min) ,   群梯运力 C = m·K·60/RTT
ρ = λ·RTT/(m·K·60) ,   5-min 输送能力 = 5C ,   5-min 需求 = 5λ
净积压速率 = max(0, λ − C)  (人/min) ,   T 分钟末积压 ≈ (λ − C)·T
WqM/D/m ≈ ½ · WqM/M/m // Allen–Cunneen：Ca²=1, Cs²=0 → 系数 ½

其中 H 为最高服务层、tf 单层运行时间、S 为单程期望停站数、ts 单次停站附加时间（开关门 + 加减速）、tp 人均进出时间。批到达率 λb = λ/K（批/min），批服务率 μb = 60/RTT（批/min），代入 m 服务台的 Erlang-C 并乘 ½ 得到候梯时间的工程近似；当 ρ ≥ 1 时该近似失效，以第 4 节仿真为准。

04 离散事件仿真（DES）验证

解析解依赖稳态与分布假设；用固定随机种子的蒙特卡洛仿真独立复算，检验公式是否可信。

4.1 仿真设计

  • 食堂：生成 Exp(λ) 到达间隔与 Exp(μ) 服务时长；维护 c 个服务台的"下次空闲时刻"，FCFS 把每位顾客分配给最早空闲的服务台；统计 Wq、W，并用 Little 定律反推 Lq。
  • 电梯：人级事件驱动——到达事件入候梯队列；电梯 j 在 freeAt[j] 发车，装载 min(K, 队列人数) 人，服务时长取 RTT·(1±10%) 以反映行程波动；记录每人候梯时间与每 0.25 min 的队列长度。
  • 输出分析（关键）：ρ → 1 时等待序列自相关极强，短运行会因"从空系统启动"产生系统性低估（实测 15,000 样本短运行偏差可达 −23%）。因此食堂采用单次长运行：预热 20,000 人丢弃初始瞬态，测量 60,000 人并均分为 20 批，用批均值法（batch means）估计 95% 置信区间；一致性判据是"解析解是否落入 CI"，而非点估计偏差。
  • 随机数用 mulberry32（避免线性同余发生器相邻样本相关的缺陷），固定种子 20261124，结果可完全复现；电梯有效样本 15,000 人 × 2 组。

5.3 决策建议

  1. 先测 λ，再谈扩容。用 3 天午餐/早高峰的分时段计数（每 5 分钟一档）得到真实峰值 λ；很多"窗口不够"其实是"下课时间过于集中"。
  2. 优先削峰。错峰 10–15 分钟、预约取餐、分批下课，是把峰值 λ 削平的最低成本手段，效果等价于 2 个窗口 / 1 部电梯。
  3. 其次提速。食堂：预打包、双收银、把"选菜"与"结算"分离（串联变并联）；电梯：目的层群控、奇偶分区、减少无效停站。
  4. 最后扩容，并留余量。按峰值 λ 配 c / m，目标 ρ ≤ 0.85，不要用平均 λ 配到 ρ = 0.95。
  5. 建立监控线。把 "Wq > 60 s" 或 "Lq > 20 人" 设为触发阈值，实时开备用窗口 / 调度电梯，比一次性固定配置更鲁棒。

"""校园高峰排队吞吐率建模 · 最小可复现脚本"""
import math, random

def erlang_c(lam, mu, c):
    a, rho = lam/mu, lam/(c*mu)
    if rho >= 1:
        return dict(rho=rho, stable=False, cap=c*mu)
    # 对数域求和，避免 a**c / c! 溢出
    terms = [n*math.log(a) - math.lgamma(n+1) for n in range(c+1)]
    mx = max(terms[:c])
    S = sum(math.exp(t-mx) for t in terms[:c])
    logS = mx + math.log(S)
    log_last = terms[c] - math.log(1-rho)
    m2 = max(logS, log_last)
    den = math.exp(logS-m2) + math.exp(log_last-m2)
    Pwait = math.exp(log_last-m2)/den
    Lq = Pwait*rho/(1-rho)
    return dict(rho=rho, Pwait=Pwait, Lq=Lq, Wq=Lq/lam,
                W=Lq/lam+1/mu, L=lam*(Lq/lam+1/mu),
                cap=c*mu, stable=True)

def sim_mmc(lam, mu, c, n=60000, warm=20000, batches=20, seed=20261124):
    """单次长运行 + 批均值法；返回 (Wq点估计秒, 95%置信区间)
    注意：rho 接近 1 时等待序列自相关极强，短运行会系统性低估，
    必须先丢弃足够长的初始瞬态，再用批均值估计方差。"""
    rnd = random.Random(seed)
    free = [0.0]*c
    t = 0.0
    per = n // batches
    batch_means, bw, bc = [], 0.0, 0
    for i in range(n + warm):
        t += rnd.expovariate(lam)
        j = min(range(c), key=lambda k: free[k])
        st = max(t, free[j])
        svc = rnd.expovariate(mu)
        free[j] = st + svc
        if i >= warm:
            bw += st - t
            bc += 1
            if bc == per:
                batch_means.append(bw / bc * 60)      # 秒
                bw, bc = 0.0, 0
    mean = sum(batch_means) / len(batch_means)
    sd = (sum((b - mean)**2 for b in batch_means) / (len(batch_means)-1))**0.5
    se = sd / len(batch_means)**0.5
    return mean, (mean - 1.96*se, mean + 1.96*se)

def rtt(H, tf, S, ts, K, tp):
    return 2*(H-1)*tf + (S+1)*ts + 2*K*tp          # 秒

def elevator_cap(m, K, R):
    return m*K*60/R                                   # 人/分钟
