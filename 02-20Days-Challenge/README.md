# 阶段二 · 微信私域 AI 应答桥接

## 一、问题定义

个人微信号没有自动应答能力。在实训室上课、做项目、睡觉的时间段，收到的重复性问题（在哪 / 多少钱 / 什么时候有空）只能等本人回，实测最长延迟 8 小时以上。这不是"懒得回"，是**异步通信的时间错配**。

需要解决的核心约束是：**在不用企业资质、不用第三方协议注入的前提下，让一个个人微信号具备自动应答能力。**

## 二、方案选型（推翻过两次）

### 方案 A：微信官方 ClawBot / iLink 通道 ❌

先试的是官方通道（LangBot 4.11.2 + `openclaw_weixin` 适配器 + Docker 部署，扫码登录成功，链路跑通）。**放弃原因**：查官方文档后确认 ClawBot 是「你与你自己的 AI 之间的私密消息通道」——其他用户无法添加、不能拉群、不会代替你给好友发消息。它能跑通，但产品定位就是自聊，不是客服。

这一点值得记录：**技术上跑通 ≠ 形态上可用**。当时日志里出现 `person_xxx@im.wechat` 与 `xxx@im.bot` 两套 ID，一度误判成"另一个号发来的"，实际只是用户身份与机器人身份的区别。

### 方案 B：第三方协议注入（WeChatFerry 等）❌

旧版微信 3.9 客户端登录直接被服务端拒绝（提示"版本过低"），注入派方案在 2026 年已整体失效。

### 方案 C：数据库读取 + UI 自动化 ✅ 采用

把"读"和"写"拆开，各自用最稳的方式：

| 环节 | 方式 | 为什么 |
|---|---|---|
| 读消息 | 解密本地 SQLite 轮询 | 只读，不触碰协议，20/20 个库可解 |
| 生成 | DeepSeek API | 1 秒出结果 |
| 发消息 | UI 自动化模拟输入 | 不注入内存，行为等同于真人打字 |

代价是发送时会抢占前台、窗口不能最小化。这是明确接受的 trade-off：**宁可牺牲后台运行，也不注入协议降低封号门槛。**

## 三、架构

```
微信窗口（小号）
   │  ① 解密本地 SQLite 轮询（只读）
   ▼
bridge.py
   ├─ 会话过滤：只处理私聊，跳过群/公众号/系统号
   ├─ 水位控制：记录每个会话最后处理的消息 seq，防重复回复
   ├─ 去重 + 频率限制：同会话最小间隔 4s，全局 120 条/小时
   ▼
上下文构造
   ├─ persona.md          → 人设卡（性格、长度示范、红线）
   ├─ knowledge/*.md      → 本地知识库（jieba + BM25 检索，零成本）
   └─ websearch.py        → 按需联网（Bing 抓取 + wttr.in 天气）
   ▼
DeepSeek API（deepseek-flash, reasoning_effort=low）
   ▼
clean_reply()  按句切分 → 超句数丢弃 → 超字数在逗号处断
   ▼
UI 自动化发送（显示名快速路径 + 三次重试兜住 COM 瞬时错误）
```

## 四、关键技术决策

**1. 为什么用 `SEARCH: 关键词` 而不是 function calling**
大模型联网有两种做法：tools/function calling，或者约定标记。选后者是因为调试成本低——模型输出什么、程序怎么判断、二次生成用了什么资料，全部落在日志里一行行可查。tools 的中间态藏在 API 返回结构里，排障时反而更绕。

**2. 为什么要四层控制回复长度**
只写"回答要短"在提示词里没有用。实测模型会输出 48 字还带三个转折和一个反问。最终做成：人设给长度示范（6 组对照）+ `max_tokens=150` + `reasoning_effort=low` + 程序硬裁到 32 字。

**3. 为什么发消息用显示名而不是 wxid**
传 wxid 每次都要重新搜索会话，单次 13 秒；传显示名走"会话复用"快速路径，1.4 秒。有重名好友时自动退回 wxid，牺牲速度换正确性。

**4. 为什么天气单独走 wttr.in**
搜索引擎对"深圳今天天气"只返回「深圳天气网提供 24 小时预报」这种导航文字，一个温度数字都没有。天气走结构化接口才能拿到 `20°C 体感18°C 湿度39%`。

## 五、复现步骤

```bash
python -m venv .venv
.venv/Scripts/pip install wechatauto-replica uiautomation pywin32 pyperclip pillow psutil jieba
cp src/config.example.json src/config.json    # 填 api_key 与 account
python src/bridge.py
```

环境：Windows 11 + 微信桌面版 4.2.0.13 + Python 3.13。微信需已登录且窗口不最小化。

## 七、已知缺陷（未解决，如实记录）

1. **发送依赖前台**：微信最小化或窗口被遮挡时会失败，重试三次后放弃该条回复
2. **COM 瞬时错误**：UIA 偶发"事件无法调用任何订户"，约每 20 次出现 1 次，靠重试兜住，未找到根因
3. **会话水位靠 seq 单调递增**：若微信重装导致 msg seq 重置，会漏读历史
4. **知识库为纯词法检索**：问"城市"匹配不到"深圳"，只能靠文档按问法写来缓解，未接 embedding
5. **联网时回复延迟翻倍**：3–4.4 s，微信端没有"正在输入"提示，用户感知为卡顿
