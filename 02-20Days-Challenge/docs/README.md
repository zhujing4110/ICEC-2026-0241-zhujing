# 功能文档索引

这些文档是写给自己看的**操作手册 + 机制说明**：每个模块怎么触发、参数在哪个范围、出问题先看哪一行日志。用词偏直白，因为写的时候就是为了三天后自己还能看懂。

| 文档 | 讲什么 | 对应迭代 |
|---|---|---|
| `聊天节奏说明.md` | 等他说完的合并窗口、思考停顿、静默策略、参数怎么调、热更新范围 | iteration-05 |
| `表情包说明.md` | 库结构、标签匹配与同义词、概率闸与最小间隔、为什么只能发图片不能发会动的贴纸 | iteration-06 |
| `收到的图片和表情说明.md` | 五类非文本消息怎么转成方括号、表情 md5 与原图来源、人工教认、能力边界 | iteration-07 |
| `看电脑说明.md` | 5 个只读工具、路径沙箱、密钥打码、三段式审批、截图与 OCR 的取舍 | iteration-08 |
| `自学与主见说明.md` | 自己出题、关键词压缩、相关性闸门、写入知识库的路径、三道刹车 | — |
| `主动发消息说明.md` | 三种触发、三道刹车、话题延续的两步走、为什么不追发 | — |
| `控制台与记忆说明.md` | 本地控制台的接口、长期记忆的提取与注入、并发写入怎么保护 | — |

## 读的顺序建议

想快速判断这个项目"做到什么程度"，按这个顺序看：

1. `聊天节奏说明.md` —— 决定它像不像真人
2. `收到的图片和表情说明.md` —— 最能体现"能力边界写清楚"而不是吹
3. `看电脑说明.md` —— 安全阀与审批链路最复杂的一块

## 一条共同原则

每份文档都有一节叫「边界」或「做不到」。这不是谦辞：**模型不知道的事，程序必须替它兜住**，否则它会顺着上下文编。写清楚边界是为了让 prompt 里也能写死同样的约束。
