# 主动发消息说明

小予现在会自己找你了。开关、时段、尺度全在 `config.json` 的 `proactive` 段，不用改代码。

---

## 什么时候会主动发

| 类型 | 触发条件 | 频率 |
|---|---|---|
| **早安** `morning` | 08:00–09:30 之间，当天还没发过 | 每天 1 次，不受日上限约束 |
| **晚安** `evening` | 21:30–22:50 之间，当天还没发过 | 每天 1 次，不受日上限约束 |
| **话题延续** `followup` | 距最后一条消息 45–480 分钟，且这个"静止点"还没延续过 | 受 `max_per_day` 约束 |

`max_per_day`（当前 **8**）只约束"话题延续"，早晚问候各保留一次独立资格 ——
否则一聊得热额度下午就烧完，晚上的"晚安"永远发不出来。

两次主动之间至少隔 `min_gap_minutes`（当前 **40** 分钟）；
话题延续还会额外随机等 0–`jitter_minutes`（当前 **25**）分钟，避免每次都是精准的 55 分钟一次。

---

## 三道刹车（都很重要）

1. **静默时段** `quiet_hours: ["23:00", "08:00"]`
   23 点到早上 8 点，一条都不发。支持跨午夜。
2. **每日上限** `max_per_day: 8`（只算话题延续，早晚问候不占额度）
3. **不追发** `no_chase: true`
   上次主动发出后对方**没回**，就不再发第二条。真人不会连发三条自问自答。
   只有静默超过 `chase_reset_hours`（默认 12 小时）才解除，相当于"换一天重新开始"。

---

## "话题延续"为什么不瞎编

分两步，这是关键设计：

1. **先判定**：单独问模型"这段记录里有没有能接下去的具体事"，只让它回 `YES: 话题` 或 `NO`。
   这一步只读原话、不做创作，编造率极低。
2. **再生成**：有话题就接着那个聊；没有就降级成"这会儿忙啥呢"这类日常问候。

所以如果某天她只发了句"在忙啥"，不是坏了 —— 是上一段对话确实没什么可接的。

实测效果：

```
记录里有"网页设计大作业、配色没定"
  → 识别话题：网页设计大作业首页
  → 生成：你那个首页配色定下来了吗 / 你打算用哪个颜色当主色？
  → 全部贴题，零编造

记录里只有闲聊（没有具体事）
  → 判定 NO
  → 生成：这会儿忙啥呢 / 四点了，这会儿忙啥呢？
```

## 改尺度

```json
"proactive": {
  "enabled": true,              // 总开关，false 就完全回到"只被动回复"
  "target": "",                 // 只对某个 wxid 主动；留空 = 自动选最近聊过的那个
  "morning":  { "start": "08:00", "end": "09:30" },
  "evening":  { "start": "21:30", "end": "22:50" },
  "followup": { "min_minutes": 45, "max_minutes": 480, "jitter_minutes": 25 },
  "quiet_hours": ["23:00", "08:00"],
  "max_per_day": 8,
  "min_gap_minutes": 40,
  "no_chase": true,
  "chase_reset_hours": 12
}
```

几个常用调法：

| 想要的效果 | 怎么改 |
|---|---|
| 再黏一点 | `max_per_day` 调到 12，`min_gap_minutes` 调到 25 |
| 回到克制状态 | `max_per_day: 3`、`min_gap_minutes: 75` |
| 别那么机械 | `jitter_minutes` 调到 40 |
| 只早上问好，别的话题不主动 | `evening.enabled: false`、`followup.enabled: false` |
| 只对某一个人主动 | `target` 填那个人的 wxid |
| 彻底关掉 | `enabled: false` |

**上限只是天花板**，真正决定一天几条的还有三个约束：每次至少隔 `min_gap_minutes`、
对方没回就不再发（`no_chase`）、以及空档超过 `max_minutes` 就不再延续。
实测当前参数下：**你有来有回的一天约 9 条（8 条延续 + 晚安），完全不理的一天只有早、晚 2 条。**

**改完 config 要重启才生效**（配置是启动时读的，不像人设文件那样热重载）。

## 自测（默认绝不发出）

```bash
.venv\Scripts\python proactive-test.py                 # 现在会不会发、为什么
.venv\Scripts\python proactive-test.py --at 08:30      # 模拟早上 8:30
.venv\Scripts\python proactive-test.py --at 22:10      # 模拟晚上 22:10
.venv\Scripts\python proactive-test.py --at 07:30      # 模拟静默时段
.venv\Scripts\python proactive-test.py --gen followup  # 只生成文案看文风
.venv\Scripts\python proactive-test.py --send          # 真的发出去（谨慎）
```

`--at` 只影响判定，文案里写的时间也会跟着变，所以模拟几点就会生成几点的语气。

## 没发？按这个顺序查

| 现象 | 先看这里 |
|---|---|
| 一点动静都没有 | `config.json` 的 `proactive.enabled` 是不是 `true` |
| 到了时段也没发 | `logs/bridge.log` 搜「暂不主动发」，原因会直接写出来 |
| 发了但没收到 | 微信窗口是否被最小化或挡住（发送要驱动前台窗口） |
| 一天只发一条就不发了 | 大概率是第三道刹车：对方没回，等她回了或过了 12 小时 |
| 报"内容为空" | 模型被思考链吃光了预算，已自动加倍重试；仍失败看 API 余额 |

`state.json` 里 `proactive` 段能直接看到当天发了几个、上次什么时候发的：

```json
"proactive": {
  "wxid_xxx": {
    "date": "2026-11-23",
    "count": 1,
    "last_at": 1795418026.0,
    "awaiting_seq": 1795412008000,
    "awaiting_at": 1795418026.0,
    "morning_date": "2026-11-23"
  }
}
```

`awaiting_seq` 有值就说明"发了但还没等到回复"，这时不会再发新的。

## 生效方法

现在跑着的还是改之前的进程，要重启：

1. 关掉正在跑的 bot 窗口（或任务管理器结束那个 python）
2. 双击 `start-bot.bat`

> 注意：如果距上次聊天已经超过 45 分钟，重启后 **1 分钟内**她就会主动发第一条（触发话题延续）。这是正常的。

# 附：连发分段

回复默认拆成两条**分别发出去**，像真人想到一句补一句，而不是一口气发一段。`|` 只是内部的拆分标记，永远不会出现在微信里。

## 怎么控制

```json
"burst": {
  "enabled": true,              // 关掉就永远单条
  "probability": 1.0,           // 1.0 = 能拆就拆；0.35 = 只有约三分之一真的拆
  "max_bubbles": 2,             // 最多拆几条（建议不超过 3）
  "gap_seconds": [0.8, 1.8]     // 两条之间的停顿，模拟打字
}
```

## 拆分规则（按优先级）

1. 模型自己用 `|` 分隔 → 按它给的位置拆
2. 没有分隔符 → 按句末标点看，但**只在每句都够 4 个字时才拆**（"好。""嗯"拆开反而像机器人抖机灵）
3. 还是一整句但超过 16 字 → 在第一个逗号处断开，避免"一坨逗号"的长消息
4. 都不满足（短句、单句反问）→ 就发一条
5. 超过条数的部分合并到最后一条

## 人设联动（重要）

`persona.md` 第 26 行控制这件事，现在写的是「多数时候拆成两条发：先应一句短的，再补一句具体的」，并明确告知竖线只是标记、不会被发出去。

**示范比规则管用**：只写规则时模型 3 次里 0 次用分隔符；加上「还差啥|来得及吗」这样的例子后立刻就学会了。现在示范有 4 条。

## 实测（probability=1.0）

```
问：配色选不出来好烦
→ 第1条「白底先试试」     第2条「不行再换」        （模型自己用 | 分了）

问：我明天要交网页设计大作业
→ 第1条「还差啥」         第2条「来得及吗」        （同上）

问：今天好累啊不想动
→ 第1条「咋了」           第2条「干啥累着了」      （同上）

问：你觉得白底好看还是灰底
→ 「白底清爽点，灰底容易闷」                        （一句说完，不硬拆）

问：你好
→ 「嗯，你好呀」                                    （短句不拆）
```

竖线泄漏检查：0 次。

## 失败处理

- 第一条就发不出去 → 整轮放弃，不硬发半句
- 第二条失败 → 保留已发出的第一条，日志记错误
- 停顿期间对方插话 → 照发完，真人也会这样

## 想调整

| 想要的效果 | 怎么改 |
|---|---|
| 别每次都拆 | `probability` 调到 0.5 |
| 完全不拆 | `enabled: false` |
| 三条 | `max_bubbles: 3`（不建议，容易像刷屏） |
| 打字更慢 | `gap_seconds` 改成 `[1.2, 2.5]` |
| 长句也不拆 | 把 `split_bubbles` 里 `len(text) >= 16` 的阈值调大 |
