# 让她能看你的电脑

## 一句话

她在微信里需要看电脑上的东西时，会**先申请**，你在控制台点「允许」，她才真的去看，然后把结果说给你。

她**只能看，不能改**。没有写文件、删文件、运行程序的通道 —— 不是靠开关关掉的，是根本没有那些代码。

---

## 她能做什么

| 工具 | 什么时候用 | 实际做的事 |
|---|---|---|
| `look_screen` | 「屏幕上写的啥」「看我在干嘛」 | 截一张屏，用 Windows 自带 OCR 把上面的字读出来 |
| `list_dir` | 「桌面有什么文件」 | 列一个文件夹里的文件和大小、修改时间 |
| `read_file` | 「读一下那个 md」 | 读文本文件（txt/md/py/json/csv 等），超 96KB 或 200 行会截断 |
| `find_files` | 「我那个文档放哪了」 | 按文件名搜索，最多 8 秒、30 条结果 |
| `sys_info` | 「现在几点」「我电脑卡不卡」 | 时间、前台窗口、内存、电量 |

### 一个必须先说清楚的事实

**她看不见画面，只读得懂字。**

她的模型是纯文本的（deepseek-flash / v4-pro，都没有视觉能力）。所以「看屏幕」对她来说不是看图，而是：截屏 → Windows 自带的 OCR 引擎识别成文字 → 那些文字进她的上下文。

这意味着：

- 屏幕上的**文字**她基本都读得到（实测 1920×1080 一次能读出约 1400 字）
- 图标、照片内容、视频画面、界面布局 —— 她一律不知道
- OCR 会有错字（「需求」可能读成「求」，图标可能读成「囗Q辑」这种乱码）
- 她**不会**因为读到乱码就瞎猜，提示词里明确禁止了编造

控制台里那张实时画面是**给你看的**，不是给她看的。

---

## 怎么用

### 正常流程

```
你：帮我看看我桌面上都有什么文件
她：等我看一眼（去控制台点个允许）        ← 这时她还没看
      ↓ 你打开 http://127.0.0.1:8765/ ，点「允许」
她：十个文件，八个是快捷方式
    就两个真东西：LSTM那个pptx和车牌识别汇报的pptx
```

从申请到她说出结果，中间隔的就是你去点那一下。

### 她什么时候会自己去看

只有你**明确要她看电脑上的东西**时。提示词里划了线：

| 你会这么说 | 她 |
|---|---|
| 帮我看看桌面 / 屏幕上写的啥 / 我那个文件放哪了 / 看我在干嘛 | 申请去看 |
| 在吗 / 今天好累 / 学 Python 看什么书 / 明天先去学校还是写作业 | 直接聊，不碰电脑 |
| 帮我把那个文件夹删了 / 帮我改下代码 | 说自己做不到，只能看不能写 |

实测 10 个场景：该看电脑的 4 条全部申请了，不该动的 6 条一次都没碰，两次越界请求都正确说了「我只能看，动不了文件」。

### 她可以连着申请几次

一次事没说清时她会再看一处，最多 3 轮（`max_rounds`）。第二轮的申请话术会变成「刚才那个不够，我再翻一个地方」，不会让你以为又从头来一遍。

## 那个窗口

浏览器打开 `http://127.0.0.1:8765/`，顶部往下第二张卡片「她的电脑」。

```
┌─ 她的电脑 ────────────────────────────────────┐
│ ┌─ 你想：看一眼你现在的屏幕 ───────────────┐  │   ← 有待批时才出现
│ │  [允许]  [拒绝]              还剩 4:52  │  │
│ └──────────────────────────────────────────┘  │
│ ┌─ 实时画面 ─────────┐ ┌─ 她做了什么 ──────┐  │
│ │                    │ │ 16:44:31 允许     │  │
│ │   你屏幕的截图      │ │  截屏并读出 104 行 │  │
│ │                    │ │ 16:44:02 申请     │  │
│ │ [x] 实时画面       │ │  看一眼你现在的屏幕 │  │
│ └────────────────────┘ └───────────────────┘  │
└───────────────────────────────────────────────┘
```

**实时画面**：每 10 秒截一张缩略图刷新。不勾就停。页面切到后台时自动暂停，不会一直截屏耗电。

**她做了什么**：每次申请、允许、拒绝、超时、失败都留一条，带耗时。

**倒计时**：默认 300 秒不批就算放弃，她会回你一句「算了，不看了」，不会一直挂着。

## 安全是怎么保证的

这是给一个会自己发消息的机器人开系统权限，所以做了四层：

### 1. 从代码上就没有写的能力

`desk.py` 里没有任何写文件、删文件、执行命令的函数。不是「开关关掉了」，是那一整类代码不存在。她要改文件只能嘴上告诉你怎么改。

### 2. 路径沙箱

只允许这些位置：

```
%USERPROFILE%\Desktop
%USERPROFILE%\Documents
%USERPROFILE%\Downloads
%USERPROFILE%\Pictures
<项目目录>      ← 她自己的项目
<工作区>          ← 你的工作区（作品集、笔记在这）
```

一律拒绝：`Windows`、`System32`、`Program Files`、`AppData`、`.ssh`、`.git`、`.venv`、`node_modules`、浏览器数据、`$Recycle.Bin`。

### 3. 密钥打码

读出来的文本会先过一遍正则：`sk-xxx`、`api_key`、`token`、`password`、`PRIVATE KEY` 全部替换成 `***`。

这条是必须的：`config.json` 就在允许范围内，里面存着 DeepSeek 的密钥。测试里专门验证了真实密钥不会出现在她能看到的文本里。

### 4. 每次都要你点

工具调用不会自动执行。她申请 → 你批准 → 才跑。同一个请求点两次，第二次会被拒（防止手抖重复执行）。

## 配置

`config.json`：

```json
"desk": {
  "enabled": true,
  "approve_timeout": 300,   // 等你批多久，超时放弃
  "max_rounds": 3,          // 一次对话最多申请几轮
  "max_tokens": 420,        // 带工具这轮的预算
  "tools": [],              // 留空=全部给；填 ["look_screen"] 就只给这一个
  "extra_roots": []         // 还想让她看别的目录，写在这里
}
```

| 想要的效果 | 怎么改 |
|---|---|
| 让她找得到 D 盘的东西 | `extra_roots: ["D:/作品"]` |
| 只给看屏幕，不许翻文件 | `tools: ["look_screen"]` |
| 等不及想快点 | `approve_timeout: 120` |
| 彻底关掉 | `enabled: false`（回到纯聊天，她不提也不调） |

改完要重启（这段和 `pacing` 不同，不在热更新范围里）。

## 实测

### 她拿到内容后怎么说话

```
你：帮我看看我桌面上都有什么文件
她：十个文件，八个是快捷方式
    就两个真东西：LSTM那个pptx和车牌识别汇报的pptx

你：屏幕上现在写的是什么，念给我听听
她：你开着 WorkBuddy，界面在加载入 DeepSeek 到微…
    右边一大片是测试记录，还有表情包 md5 匹配的说明

你：看看我现在在干嘛
她：在折腾 WorkBuddy 那个控制台面板吧
    写能力说明那块
```

「看看我现在在干嘛」那条最有意思：她只拿到 OCR 文字，却推断出你在做什么。没有编造。

### 性能

```
截屏               0.03 秒
OCR（放大 2 倍）    0.9 秒，约 1400 字
列目录 / 读文件    毫秒级
找文件             最多 8 秒（硬上限）
实时画面（jpeg）    47KB / 张
```

OCR 放大 2 倍是必要的：原尺寸直接读，「需求」会读成「求」，「给」读成「蛤」。

## 已知限制

- **看不到画面**。这是模型能力决定的，不是实现问题。要真看得懂图，得换视觉模型。
- **OCR 有错字**。界面小字、浅色字、图表里的字识别率明显下降。她读到乱码不会瞎编，但可能理解偏。
- **只读**。想让她"帮你改"是不行的，她只能告诉你怎么改。
- **找不到文件不代表没有**。搜索有 8 秒上限，深层目录可能扫不到。搜索范围也只在上面那几个根目录里。
- **批准要你人在**。你不在电脑前，她申请了也只能超时放弃。
