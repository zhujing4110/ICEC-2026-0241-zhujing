# 表情包说明

她自己去网上搜表情包、下载、压缩、存起来，聊天时按情绪挑一张发出去。

---

## 一句话版本

平时不吭声，等你说到"改第八版了""奶茶打翻在键盘上"这种话，她可能先回一句，再甩一张无语的图过来。

五轮对话实测：发标记 1 次（20%），场景是对的（奶茶打翻 → 无语），正文没有被标记污染。

---

## 她怎么攒

| 步骤 | 做什么 |
|---|---|
| 1 | 从队列取一个词：先是聊天时想发却没有的情绪，然后是没攒够的情绪，最后按兴趣轮换 |
| 2 | 360 图片搜「词 + 表情」，取前 15 条 |
| 3 | 标题必须含这个词（挡掉"无"字字典页这类误命中） |
| 4 | 下载 → 校验体积/尺寸/长宽比 → 等比缩到 320px → 存 PNG |
| 5 | 平均哈希去重（同张图被转载到多个站也拦得住） |
| 6 | 写进 `stickers/index.json`，带标签、来源、使用次数 |

**什么时候攒**：09:30–23:00，每 2 小时一次，每次 3 张，攒到 160 张就停。

**为什么按"数量最少优先"**：某个情绪只有 1 张，她聊到那个情绪时容易挑不到。补缺比平均铺开有用。

---

## 她怎么挑：五道闸

模型想发表情时，会在正文后面另起一行写：

```
STICKER: 不开心
```

从"她想发"到"你真的看到图"，中间有五道：

| # | 闸门 | 卡住会怎样 | 在哪调 |
|---|---|---|---|
| 1 | **模型愿不愿意开口** | 压根不写 STICKER 行 | persona + system prompt |
| 2 | **词能不能对上标签** | 写了个库里没有的词，挑不到 | 同义词兜底 + 标签注入 |
| 3 | **冷却时间** | 距上一张不到 N 分钟，跳过 | `min_gap_minutes` |
| 4 | **概率闸** | 随机拦掉，只发文字 | `use_probability` |
| 5 | **发送成功** | UIA 贴图失败 | 一般不用管 |

第 4 道只拦**文字配图**。如果她这条只发一个表情、不写字，那就是回复本身，拦掉等于不回，所以不受概率闸限制。

## 为什么之前几乎不发图（实测）

改之前 161 条回复里只成功发出过 **1 次**图。逐道查下来，是三个问题叠在一起：

### 1. 两道指令都在叫她"少发"

`persona.md` 写着「十次里用一两次就够，你平时聊天很少发图」，
`system prompt` 又写了一遍「多数时候别发，十次里一两次就够」。

模型看到两次"很少"，就真的很少。这是最主要的原因。

**改成**：只描述"什么时候该发"（对方带情绪时）、"什么时候不该发"（问事、办正事、安慰人），
不再给频率数字。

### 2. 她不知道库里有什么标签，只能猜

改之前 prompt 里虽然列了标签，但写着「多数时候别发」，模型注意力全在"别发"上，
真要发时又自己造词 —— 实测出现过 `STICKER:喜滋滋`、`STICKER:烦`，库里都没有，直接落空。

**改成**：明确写「情绪词**只能**从这几个里挑，挑列表外的词挑不到图，等于白写」。
另外在挑图端加了一层同义词兜底（`喜滋滋→开心`、`烦→不开心`、`卧槽→震惊`），
万一还是造了词，也有机会命中。

### 3. token 预算被思考链吃光，STICKER 行被截掉

`max_tokens` 原来是 150。思考和正文吃满之后，最后那行 STICKER 就没地方写了，
而且因为正文非空，`deepseek_chat` 不会重试，静默丢失。

同一批 10 个场景对比：

```
max_tokens=150 → 命中 2/10
max_tokens=400 → 命中 4/10
```

**改成** `max_tokens: 320`。回复长度本来就有 `clean_reply` 的 32 字上限兜底，
放宽预算不会让话变长，只是给最后一行留位置。

### 顺带修掉的一个语义 bug

挑图原来是子串匹配，`喜滋滋`（→开心）会匹配到标签为 **「不开心」** 的图，
情绪正好相反。现在加了极性检查：带「不/没/别」开头的标签和不带的不互相匹配，
并且精确相同的词优先（+5 分），包含关系次之（+2 分）。

## 实测效果

同一批 10 个天然适合配图的场景（累、吐槽、社死、开心、熬夜…），
在真实条件下（标签已注入、库是当前这 9 张）：

```
今天累死了，加班到十点        → 咋了|饭吃了没
老板又改需求了，第三版了       → 改到第几版了这是      [图] STICKER:累了  ← 库里没有
刚在电梯里跟人撞了个满怀       → 撞到谁了|认识的吗     [图] STICKER:怎么这样
明天要早起，但现在已经一点了    → 那你还不睡          [图] STICKER:干嘛
地铁上有人外放抖音，声音巨大    → 外放是真烦人|整车厢都得听 [图] STICKER:怎么这样
我画的图被老师当范例展示了     → 诶 厉害啊|被当范例了
```

命中 **4/10 = 40%**（改之前同一批是 10%）。其中 3 张挑到了图，1 张因为库里没有"累了"落空。

40% 是"情绪场景里的配图率"，日常问事、办正事的对话基本不会配 —— 整体看下来
大约五六条回复出一张图，这个密度接近真人。

> 落空的那个词会被记进待收队列，下次自动上网补图（见下面 `collect_enabled`）。
> 如果你不想要她再自己收图，把 `collect_enabled` 关掉，缺的图手动传。

## 三个必须知道的限制

**1. 发出去的是图片，不是会动的表情**

微信 4.x 的表情消息在本地库里是加密的，没有发送接口（只有收+截图的 `EmojiMessage.capture`）。所以走的是「剪贴板粘贴图片」路线，对方看到的是一张图，不是能动的贴纸。

**2. 会短暂占用剪贴板**

发图前把你的剪贴板内容（文本）存下来，发完还回去。实测还原成功。**但如果你原本复制的是图片或文件，还原不了**——那些格式拿不到可靠快照。

**3. Bing 图片中文搜不准，换了图源**

早期版本用 Bing，「无语 表情包 微信」搜回来是 Valorant 海报和字典页。三个图源实测：

| 图源 | 结果 |
|---|---|
| 360 图片 | 可用，标题就是"无语表情包合集" |
| Bing 图片 | 切词崩坏，返回游戏海报 |
| 百度图片 | JSON 接口返回空 |
| 搜狗图片 | 返回空 |

现在 360 为主、Bing 兜底。搜索词也从「词 + 表情包 + 微信」改成「词 + 表情」——加上"微信"反而把结果带到"微信表情包新闻"文章页。

## 配置

```json
"stickers": {
  "enabled": true,
  "dir": "stickers",
  "max_items": 160,            // 仓库上限，满了不再攒
  "use_probability": 0.95,     // 文字配图的通过率
  "min_gap_minutes": 5,        // 两条表情之间至少隔多久
  "collect_enabled": true,
  "collect_interval_hours": 2,
  "collect_count": 3,          // 每次攒几张
  "collect_start": "09:30",
  "collect_end": "23:00",
  "emotions": ["无语","开心","累了","疑惑","尴尬","生气","加油","晚安"],
  "interests": "猫、咖啡、画图"
}
```

**`stickers` 这一段支持热更新**：保存 `config.json` 后最多 2 秒自动生效，不用重启，
日志里会出现一行「参数已热更新（stickers）：… 表情包概率 0.95」。

常用调法：

| 想要的效果 | 怎么改 |
|---|---|
| 更爱发图 | `use_probability: 1.0`，`min_gap_minutes: 2` |
| 几乎不发 | `use_probability: 0.2` |
| 攒快一点 | `collect_interval_hours: 1`、`collect_count: 5` |
| 只要某类 | `emotions` 只留你想要的，`interests` 清空 |
| 彻底关掉 | `enabled: false` |

## 控制台：查看和修改

打开 `http://127.0.0.1:8765/`，页面下方的「表情包」卡片就是全部入口。

### 看

- 标题旁：`43 张 · 2.4 MB · 无语 6 · 开心 6 · 疑惑 6 · 累了 5 …`（按数量排，最多显示 8 个标签）
- 下面是**全部**缩略图，不截断（库上限 160 张都能看到、都能操作）
- 每张图底部：标签 + `·3` 表示这张已经发出去 3 次
- 鼠标移上去，左上角出现「改」、右上角出现「删」

### 改

| 操作 | 怎么做 | 说明 |
|---|---|---|
| 改标签 | 悬浮 → 左上「改」 | 多个用逗号隔开，最多 4 个 |
| 删图 | 悬浮 → 右上「删」 | 文件和索引条目一起清 |
| 传本地图 | 「传本地图」→ 选图（可多选） | 一次给这批图打同一个标签 |
| 手动收 | 输入词 → 「去收表情包」 | 填「猫」立刻上网搜，留空按顺序自动挑 |

**标签是挑图的唯一依据。** `pick()` 只按 tags 匹配，把「开心」写成「搞笑」，说"开心"的时候这张永远不会被选中 —— 这是改标签最主要的原因。

导入规则：

- 前端先缩到 512px 再传（手机截图十几 MB 也能直接扔进来），后端再统一转 PNG、缩到 320px 内
- 和自动收集共用去重：同一张传两次会被拦（"这张已经在库里了"），几乎一样的图也会被拦
- 标签可留空，默认归到「其他」；不能全空

## 文件在哪

```
stickers/
  index.json          索引：标签、来源、使用次数、哈希
  st_<时间戳>_<md5前6位>.png
```

`index.json` 可以直接手改，但**控制台已经能改标签、删图、导入了**，一般不用碰它。
真要手删文件，记得同步删索引条目，否则缩略图会破图 —— 用控制台的「删」最稳。
