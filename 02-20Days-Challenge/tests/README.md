# 测试脚本

全部离线可跑：不连接微信、不调用模型（个别脚本用假模型注入返回值），因此可以反复回归，不会给真实账号发消息。

## 怎么跑

```bash
cd 02-20Days-Challenge
python tests/pacing-test.py
```

脚本都会把状态写到临时目录，**不读也不写真实的 `state.json`**。这是踩过坑之后加的约束：早期有一版测试忘了重定向，往真实会话历史里写了三条假记录。

配置方面：仓库里只有 `config.example.json`（真实 config 含密钥，不入库），脚本检测到没有 `config.json` 时自动退回示例配置。

个别脚本（`desk-test.py`）会真实截屏并跑 OCR，需要先装 winrt 那几个包；没装时脚本会跳过这一项并说明原因。

三个脚本需要真机环境，不能在别的机器上跑：`inbox-test.py`（要读真实微信消息库）、`proactive-test.py`（要连微信账号）、`sticker-probe.py`（要真实调用模型）。其余七个纯离线。

## 一条经验

**能写成断言的，就别靠"看着像对的"。** 表情包触发率那个 bug 一开始就是"感觉发得少"，改成逐道闸统计日志计数之后，三个原因十分钟内全暴露了。
