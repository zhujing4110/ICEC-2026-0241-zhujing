## 二、脱敏：一次差点改错的批量替换

要把真实昵称、wxid、密钥从代码和日志里抹掉。三类替换：

- `wxid_xxx` → `wxid_MAIN_MASKED` / `wxid_BOT_MASKED`
- 真实昵称 → 主号A / 小号B
- API Key → `YOUR_DEEPSEEK_API_KEY`

**差点出事的一步**：把「予夏」当成主号昵称全局替换成「号主」，结果人设卡里出现「名字：号主」。
实际「予夏」是我给这个 AI 起的**角色名**（小予），「忆雾」才是主号昵称。
两者混同会把「她是小予」改写成「她是号主」，人设直接崩。

**教训**：批量替换昵称之前，必须先判断这个词是「角色名」还是「账号名」——判断错了，代码能跑、话全变味。

脱敏后复检：`api_key` 为占位符，439 行日志里无 `sk-`、无真实 wxid、无真实昵称。

## 三、推送的三个坑（每个都卡了十几分钟）

1. **`origin` 被占位符污染**：把文档里的 `https://github.com/你的用户名/...` 原样 `remote add`，
   之后既报 `already exists` 又报 `repository not found`。解法：`git remote set-url` 重指。
2. **GitHub DNS 污染**：`github.com` 被解析到 `20.247.166.64`（不通），真实可达地址是 `140.82.112.3`。
   附带发现 `ssh.github.com` / `api.github.com` / `codeload.github.com` **都没有被污染**。
3. **git 不读系统代理**：浏览器能开 GitHub 是因为走了 Clash，git 直连撞坏 IP 就超时。
   在仓库 `.git/config` 配 `http.proxy / https.proxy = http://127.0.0.1:7897` 解决。
   hosts 方案要管理员权限，未采用。

另外补了一条环境改动：把 PortableGit 的 `cmd` 目录写进用户 PATH（原先 PATH 里没有 git，
新开的终端会报「无法识别 git」）。
