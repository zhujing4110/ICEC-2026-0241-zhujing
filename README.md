## 二、选题

### 阶段二：工坊开放式项目挑战营

**选项：项目四 — 解决校园真实痛点的轻量化实用程序研发与日常运行日志验证**

**作品名称**：微信私域 AI 应答桥接（WeChat AI Reply Bridge）

**要解决的问题**：个人微信号无法像客服系统那样自动应答。上课、实训、睡觉时收到的重复性问题（在哪、多少钱、什么时候有空）只能等本人回，回复延迟常常超过 8 小时。市面上的方案要么是公众号（需要对方先关注，形态不对），要么是第三方协议机器人（封号风险高、已随微信 3.9 客户端下线而失效）。

**做法**：不注入、不劫持协议，改为两条腿——读消息走本地 SQLite 解密（只读），发消息走 UI 自动化（模拟真人输入）。中间接大模型生成回复，再接人设卡与本地知识库控制语气和事实。

**为什么符合"项目四"的要求**：这个程序已经在本机连续运行，`process_logs/` 里是它真实产生的运行日志（含时间戳、收发明细、报错栈），不是补录的。中途发生的八轮缺陷修复与能力扩展都有对应的迭代记录与修复前后对比。

**三天里它从"能应答"长成了什么**（每一轮都是被真实使用推翻后改的）：

| 能力 | 起因 | 结果 |
|---|---|---|
| 等他说完再答 | 使用者习惯一句拆三四条发，回复总接在半截话上 | 合并窗口 + 思考停顿，间隔从 18 秒压到 4–9 秒 |
| 会发表情包 | 文字回复太干 | 触发率 10% → 40%，失败原因逐闸定位 |
| 收得到图/表情/语音 | 非文本消息被一行 `type != "文本"` 过滤掉且水位照推 | 新增 `inbox.py`，表情按 md5 认出情绪 |
| 能看屏幕（只读） | "你能不能看看我电脑上这个" | 5 个只读工具 + 截屏 OCR + 每步人工批准 |
| 有记忆、会自学 | 每次聊天都从零开始 | 一人一份记忆 + 自己搜题写笔记 |
| 主动找你 | 只回不说是客服，不是朋友 | 早安/晚安/话题延续，三道刹车防打扰 |

## 五、目录里的文件怎么跑

`src/` 是可运行代码，但**不包含任何密钥**（`config.example.json` 里的 key 是占位符）。

```bash
# 1. 建虚拟环境
python -m venv .venv

# 2. 装依赖（看屏幕的 OCR 需要额外装 winrt 的几个包）
.venv/Scripts/pip install wechatauto-replica uiautomation pywin32 pyperclip pillow psutil jieba
.venv/Scripts/pip install winrt-Windows.Media.Ocr winrt-Windows.Graphics.Imaging winrt-Windows.Storage.Streams winrt-Windows.Foundation winrt-Windows.Globalization winrt-runtime

# 3. 复制配置并填入自己的 key
cp src/config.example.json src/config.json   # 然后编辑 api_key 和 account

# 4. 启动（前台，会显示日志）
python src/bridge.py

# 或者后台静默启动
python src/launch.py
```

启动后控制台在 http://127.0.0.1:8765 ，可以看消息流水、改人设、管理表情包、点「允许」让她看屏幕。

运行环境：Windows 10/11 + 微信桌面版 4.x（本项目在 4.2.0.13 上验证）+ Python 3.13。

## 六、必须说明的风险与局限

1. **这不是微信官方接口**。发送端依赖 UI 自动化，属于灰色地带。整个项目只在个人小号上使用，不群发、不主动加好友、不接商业场景。
2. **微信窗口不能最小化**，发送时会短暂抢占前台。
3. **能力边界**：商品实时价格、需登录才能看的内容查不到；这类问题程序被约束为"直说查不到"而不是编造。
4. **模型没有视觉能力**。她能知道"你发了一张图/一个表情包"，但看不到画面、听不到语音。表情包靠 md5 与自己的库比对认情绪，图里是什么只能问对方。"看屏幕"是截屏后走 Windows OCR 认字，**不是真的看见画面**，所以图里的内容、字太小的界面她都不知道。
5. **看电脑只能看，不能动**：不写文件、不删除、不运行程序。而且每一步都要人工在控制台点「允许」，一次事可能要点两三次。
6. **表情库只有 9 张**，缺「累了 / 开心 / 尴尬」这类高频情绪，情绪词挑不到图时这一轮就不配图。
7. **OCR 与日志都有上限**：界面小字、浅色字识别有限，滚动区域只看得到当前一屏；日志没有轮转，单文件已累积 220 KB / 2231 行。
8. 阶段一进度不一：**课题 10 已完成**（脚本可复现，但人工耗时一列仍是估算）；**课题 04 尚未实测**，`raw_data/task04-queue-throughput.csv` 是 15 行空表，不是测量结果。
